## Hashi indexer 2.0

Adds **monitoring**: the indexer now exposes Prometheus metrics, so the Moonlet agent can collect them and Grafana can show whether the indexer is healthy and what Hashi is doing. Nothing about the stored data changes.

### What's new
- **`/metrics` on port 9199**, published on the host's **loopback only** (the agent reads it from the same machine; nothing is reachable from outside). Set `METRICS_PORT` to change it, `0` turns it off. A failure to serve metrics never stops the indexer.
- **Indexer health:** per-job runs by outcome, duration histogram, time of the last success and whether the last run worked; whether every event type has caught up with the chain; whether the history window is stored; Sui GraphQL request counts and latency; process memory, CPU and event-loop delay.
- **Hashi state, as of the last snapshot:** hBTC supply, BTC reserve, backing ratio, UTXOs, pending and completed deposits and withdrawals, epoch, paused flag, registered operators.
- **Database:** size, size and rows per table, events stored and newest event per type.
- **`monitoring/grafana-dashboard.json`:** a Grafana dashboard (import it and pick the data source). Suggested alert conditions are listed in the README.
- All metrics are named `hashi_indexer_*` and carry no `network` label: the agent adds `network` and `hostname`.

### Deploy
On each Hashi host, from the existing clone:

```bash
cd ~/sui-bridge/hashi-indexer
# optional: add METRICS_PORT=9199 to .env (that is the default)
./deploy.sh hashi-indexer-v2.0
```

Then, in the admin UI, give port **9199** its labels on both servers (Autodiscovery config, port label mapping), for example `blockchain=sui, server_type=rpc, node_type=hashi-indexer`, and check `moonlet-agent stats` lists `http://127.0.0.1:9199/metrics`. See "Monitoring" in `hashi-indexer/README.md`.

This release also includes the earlier `deploy.sh` fix: a checkout with untracked files is refused instead of building from it.

### Upgrading
No database migration. The database, its volume and the stored history are untouched; the indexer container is rebuilt and restarted (a few seconds without events, which the next run catches up). Rolling back is `./deploy.sh hashi-indexer-v1.0`: the only effect is that metrics stop.

### Known limits
- The agent samples every 2 minutes, so metrics have that resolution.
- Nothing probes the operators' or the Guardian's endpoints yet, so there is no "operators online" metric.
