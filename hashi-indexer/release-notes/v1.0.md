## Hashi indexer 1.0

First release. The indexer keeps Hashi's history in a small Postgres, so the analytics dashboard can show what the chain does not keep: how supply, reserve, UTXOs and queues changed over time, and what happened to every request.

### What it does
- **Snapshots every 10 minutes:** hBTC supply, the BTC the committee holds, UTXO count, deposit and withdrawal queue sizes, the committee of each epoch. These power the "Supply, reserve and queues over time" chart on the dashboard's Hashi Overview tab.
- **Every request, stored:** deposits, withdrawals and withdrawal batches (with miner fees), read from Hashi's on-chain tables on mainnet. Their status moves forward as they are approved, signed and confirmed.
- **Request events, stored:** the full lifecycle (requested, approved, confirmed, picked for processing, expired and cancelled). Expired deposits and cancelled withdrawals are applied to the stored requests, which the chain itself forgets once it deletes them.
- **How far back:** mainnet reads the **entire history** since the first Hashi request (22 Oct 2026). Testnet reads the **last 7 days** of events (`BACKFILL_DAYS`), because testnet has millions of requests.
- **One stack per network and per Hashi host:** `postgres:16-alpine` plus one indexer, with a writer role for the indexer and a **read-only role for the dashboard**.
- **Safe to run and restart:** writes are idempotent, a long backfill resumes where it stopped, an outage makes the job report failure (and the healthcheck with it), and two copies never overlap.

### Deploy
On a Hashi host (testnet first), from the sparse clone described in `hashi-indexer/README.md`:

```bash
cd /opt/sui-bridge/hashi-indexer
./deploy.sh hashi-indexer-v1.0
```

You need Docker, outbound HTTPS (GitHub, Docker Hub, npm and the Sui GraphQL endpoint), a `.env` created on the host, and a firewall rule that lets the dashboard reach port **5433**. The dashboard shows the history once `SUI_HASHI_POSTGRES_URL` (and `SUI_HASHI_TESTNET_POSTGRES_URL`) are set; without them it keeps reading live from Sui.

### Verified
- A full mainnet backfill from scratch reconciles with the chain to the satoshi: minted deposits minus burned withdrawals equals the on-chain supply and reserve, and the stored requests match the successful `deposit()` and `request_withdrawal()` transactions counted straight from Sui.
- Restarts, interrupted and capped backfills, passwords with special characters, and a simulated Sui outage were tested locally.

### Known limits
- Testnet stores events only: its request and batch tables are too large to read, so those tables stay empty there.
- Nothing yet stores Bitcoin confirmation counts or probes the operators' and the Guardian's endpoints.
- The Postgres connection is not encrypted: restrict port 5433 to the dashboard's addresses (or a private network).

### Upgrading
This is the first release, so there is nothing to migrate. Later releases apply their database migrations on start, and rolling back is `./deploy.sh` with the previous tag.
