## Hashi indexer 2.1

A small update to the metrics added in 2.0. Nothing about the stored data changes.

### Fixed
- **`hashi_indexer_db_table_rows` showed 0 for small tables.** It read Postgres's `pg_class.reltuples`, which stays at -1 until a table is first vacuumed or analyzed, so a table such as `hashi_snapshots` or `hashi_committee_epochs` looked empty (and `hashi_events` lagged behind by a few percent). It now reads `n_live_tup`, which Postgres keeps up to date as rows are written. The value is still Postgres's own count rather than an exact `count(*)`; `hashi_indexer_events_in_db` has the exact event counts.
- **`hashi_indexer_process_cpu_seconds_total` is now declared as a counter** (it only ever goes up), matching its name. Queries such as `rate(...)` are unaffected.

### Deploy
```bash
cd ~/sui-bridge/hashi-indexer
./deploy.sh hashi-indexer-v2.1
```
No migration and no new settings. The database and the stored history are untouched. Rolling back is `./deploy.sh hashi-indexer-v2.0`.
