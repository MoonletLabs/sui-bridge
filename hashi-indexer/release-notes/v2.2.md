## Hashi indexer 2.2

Fixes the label of the job metrics added in 2.0. Nothing about the stored data changes.

### Fixed
- **The job metrics are now labelled `task` instead of `job`** (`hashi_indexer_job_runs_total`, `hashi_indexer_job_duration_seconds`, `hashi_indexer_job_last_success_timestamp_seconds`, `hashi_indexer_job_last_run_ok`). `job` is the scraper's own label: when a metric also carries `job`, Prometheus and VictoriaMetrics rename it to `exported_job` and set `job` to the scrape job (`moonlet-servers`). In Grafana both jobs showed up under the same name, and any query or alert written on `{job="events"}` matched nothing.

### Upgrading
- **Queries and alerts that use the job label must use `task`**: `hashi_indexer_job_last_success_timestamp_seconds{task="events"}`. Until a host runs 2.2 its series still carry `exported_job`.
- Re-import `monitoring/grafana-dashboard.json` (it uses `task`).
- No migration, no new settings. The database and the stored history are untouched.

```bash
cd ~/sui-bridge/hashi-indexer
./deploy.sh hashi-indexer-v2.2
```

Rolling back is `./deploy.sh hashi-indexer-v2.1` (the label goes back to `job`).
